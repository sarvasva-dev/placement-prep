A computer network is a collection of interconnected autonomous devices—such as computers,
servers, phones, printers, switches, and routers—that communicate and share resources using
agreed rules called protocols.
A network can use:
Wired media: twisted-pair cable, coaxial cable, optical fibre.
Wireless media: radio waves, Wi-Fi, microwave, cellular, satellite.
Share hardware such as printers and storage.
Share files, databases, applications, and Internet access.
Support email, messaging, web browsing, cloud platforms, video calls, and remote access.
Allow centralized administration, backup, authentication, and security policies.
Reduce cost by allowing common resources to be used by many users.
Support scalability: new devices and services can be added as requirements grow.
A computer network is an interconnection of two or more autonomous computing
devices through communication links for the purpose of sharing data, resources, and
services.
Data communication is the exchange of data between two or more devices through a
transmission medium. The information may be text, numbers, images, audio, video, or
program data.
Data communication is successful only when the sender and receiver follow compatible rules
for formatting, addressing, timing, transmission, and error handling.

A protocol is not merely an optional software feature. Communication between different
devices is reliable only when they agree on protocol rules, including data format, timing,
addressing, sequencing, and error control.
A good data-communication system is evaluated using four principal characteristics.
Data must reach the correct destination, intended device, process, or user. A packet delivered
to the wrong host is not a successful delivery.
Data must arrive without unwanted alteration. Bit errors, missing bytes, duplication, or
corrupted frames reduce accuracy. Error-detection and correction mechanisms help maintain
accuracy.
Data must arrive when it is needed. For stored files, a small delay may be acceptable. For live
audio, online gaming, remote control, and video conferencing, late data can be useless.
Jitter is the variation in packet delay or packet-arrival time. It is especially harmful to real-time
audio and video.
Example: if voice packets should arrive every 20 ms but some arrive after 20 ms and others after
70 ms, the sound may become choppy even if no packet is lost.

A parity bit is an additional bit added to a data unit to make the total number of 1s either even
or odd.
Set the parity bit so that the total number of 1s, including the parity bit, is even.
Example: Data = 1011001 has four 1s. For even parity, parity bit = 0.
Set the parity bit so that the total number of 1s, including parity, is odd.
Example: Data = 1011001 has four 1s. For odd parity, parity bit = 1.
Simple parity detects any odd number of changed bits, but it cannot detect an even number of
changed bits. It also cannot identify the erroneous bit.
In a checksum method, the sender divides data into fixed-size words, adds them using one’s-
complement arithmetic, and sends the complement of the sum as the checksum. The receiver
repeats the calculation and checks whether the result is valid.
Checksum is used by several Internet protocols, but it is generally weaker than a well-designed
CRC for detecting burst errors.

Cyclic Redundancy Check (CRC) is an error-detection technique based on modulo-2 binary
division. The sender appends a calculated remainder, called the CRC or Frame Check Sequence
(FCS), to the data. The receiver divides the received codeword by the same generator; a non-
zero remainder indicates that an error has been detected.
CRC does not prove that received data is absolutely error-free when the remainder is zero. It
means that no error detectable by that CRC generator has been found. In exams, write: “The
frame is accepted if the remainder is zero; otherwise it is considered erroneous.”

The data-link layer provides node-to-node delivery. It detects and manages lost, damaged, or
duplicate frames over a single link.
Error-detection code: parity, checksum, CRC.
Sequence numbers: identify frames and detect duplicates.
Acknowledgement (ACK): confirms successful receipt.
Negative acknowledgement (NAK): asks for retransmission, where used.
Timers: detect a missing acknowledgement.
Retransmission: sender sends the frame again.
ARQ: Automatic Repeat reQuest protocols.
1. Sender transmits one frame.
2. Sender waits for an ACK.
3. If ACK arrives correctly, sender transmits the next frame.
4. If the timer expires or a NAK is received, sender retransmits the frame.
Advantage: simple.
Disadvantage: inefficient on long-delay or high-bandwidth links because the sender remains
idle while waiting.

A correct exam answer should distinguish the suite as a whole from TCP and IP individually.
1. Interconnects heterogeneous networks: allows devices on different local and wide-area
networks to communicate.
2. Provides logical addressing: IP identifies source and destination interfaces using IPv4 or
IPv6 addresses.
3. Supports routing: routers forward IP packets toward destination networks.
4. Provides process delivery: TCP/UDP port numbers direct data to the correct application
process.
5. Supports reliable transfer when TCP is used: TCP sequences data, acknowledges receipt,
retransmits losses, and delivers data in order.
6. Supports fast best-effort transfer when UDP is used: UDP is useful where low overhead and
timeliness matter more than guaranteed delivery.
7. Performs segmentation and reassembly: upper-layer messages can be divided into
transport segments and reconstructed at the destination.
8. Provides flow and congestion control through TCP: TCP controls sender rate to protect the
receiver and respond to network congestion.
9. Supports applications through application protocols: HTTP/HTTPS, DNS, SMTP, and many
other protocols operate over TCP/IP.
10. Supports extensibility and interoperability: common standards allow diverse hardware,
operating systems, and networks to communicate.
TCP performs error detection, ordered reliable delivery, and retransmission; it does not
generally “correct” a corrupted packet in place.
IP offers best-effort delivery. It does not guarantee delivery, order, or reliability.
Security is not automatically provided by TCP/IP alone. Protocols such as TLS, IPsec, SSH,
and VPN technologies may add security services.

A MAC (Media Access Control) address is a link-layer hardware identifier used for delivery
within a local network segment. In common Ethernet and Wi-Fi use, it is a 48-bit identifier
written as six hexadecimal octets.
Example:
00:1A:2B:3C:4D:5E
A MAC address is typically assigned to a network interface by its manufacturer, but it can often
be changed or spoofed in software. Therefore, do not write that MAC addresses “can never be
changed.”

When a device wants to send data to another device on the same IPv4 LAN, it knows the target
IP address but needs the target MAC address for the Ethernet frame. It uses ARP (Address
Resolution Protocol) to map IPv4 address to MAC address.
For IPv6, Neighbor Discovery Protocol performs a similar role; classic ARP is not used.
For a remote destination, the source normally sends the Ethernet frame to the MAC address of
its default gateway, while the IP packet retains the remote destination’s IP address. At each
router hop, the Layer-2 frame/MAC addresses change, but the source and destination IP
addresses normally remain end-to-end.

IPv6 (Internet Protocol version 6) uses 128-bit addresses. It was designed to solve IPv4 address
exhaustion and improve Internet-layer functionality.
The number of possible IPv6 addresses is:
This is an extremely large address space.

Compressed form:
2001:db8::1
An IPv6 address consists of eight groups of four hexadecimal digits.
Leading zeros inside a group may be omitted.
One consecutive run of all-zero groups may be compressed using ::.
:: may be used only once in one IPv6 address to avoid ambiguity.
Example:
2001:0db8:0000:0000:0000:ff00:0042:8329
